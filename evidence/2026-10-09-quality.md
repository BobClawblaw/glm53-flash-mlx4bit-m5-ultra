Notes:

- long-context: the check sizes documents nominally (8k-250k). GLM's tokenizer makes them about 20% shorter, so the
  "128k" level is about 102k tokens and fits the 131,072 window; "250k" does not run at this context.
- tools: the 3 misses are the checker's exact match. Each picked the right function with the right core values and
  added an optional field (`label`) or a fuller place name ("louvre museum, paris").
- ifeval: the replies are complete and well formed; the model breaks the rule ("no commas", "only JSON", "exactly 2
  paragraphs", lowercase hashtags). With thinking on, 6 of the first 10 misses passed, using 4k-25k characters of
  reasoning each. The recipe defaults to thinking on; the numbers above are thinking off.
- Tool calling outside the suite (hermes-style, `temperature` 0.6): thinking off and on, streamed and not, all
  returned valid `tool_calls`. Parallel calls with a `tool`-result round trip answered correctly. The user's hermes
  agent sent 33 requests from another machine after the restart, all 200.
- The first suite run lost ifeval/gsm8k/mgsm/mmlu to dataset downloads: python.org's Python 3.14 has no CA bundle.
  `mac/external.py` now sets `SSL_CERT_FILE=/etc/ssl/cert.pem`.
- Part 2 stopped during MMLU when a restart was killed by memguard: another agent's 47 GB model server held
  memory, and the two models do not fit together. memguard stopped the load at 16.4 GiB free with nothing else harmed.
  Part 3 reran MMLU and the rest once that server had gone.
